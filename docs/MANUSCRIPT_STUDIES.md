## Running a standalone study without changing its mathematics

1. Use a new writable study workspace outside the repository's source tree. Copy the desired standalone script there. Do not add all standalone scripts to the active core benchmark path.
2. Extract `inputs/supplementary_reference.zip` into that workspace. It creates `revision_results/` with the archived CSVs, coordinate caches, and settings. Keep a separate untouched archive; postprocessors may write into the extracted working copy.
3. Open MATLAB R2024b in the study workspace and run the copied script by name. Packing scripts require Image Processing Toolbox. The included read-only geometry/LS audits use base MATLAB. `R2_C28_RSA_RSD_StatisticalComparison.m` optionally uses `tcdf` for Welch p-values when Statistics and Machine Learning Toolbox is available; it does not fabricate those p-values if unavailable.
4. Read each script's user-settings block first. Retain its seed policy, sampler, budgets, convergence criteria, and target list when reproducing that study. Do not silently substitute the core benchmark's settings.
5. Prefer the read-only `R2_C21_Consolidated` default `mode="audit"`, `R2_C39_IndependentSpatialAudit`, and `R2_C32_FullPrecisionCSV_Audit` when verifying existing outputs. All three were executed successfully on scratch copies of archived data during this preparation.

### Input details and unresolved dependencies

- `R1_C1_FocusedAblation` searches for `R1_C1_raw.csv` in the working directory or directly in `revision_results/`. Copy the archived `revision_results/R1_C1_BenchmarkAnalysis/R1_C1_raw.csv` to that expected location to reuse the baseline. Do not confuse it with the separate 240-case VGPP/RSA dataset.
- `R1_C2_OrderingDecomposition_Efficient` can generate missing configurations; for cached-only analysis set its documented `generateMissing=false` option in a separate working copy. MC postprocessing reads the Full_VGPP cache for seeds 9301/9302, 9401/9402, and 9501/9502. The additional phi70/seed9401 cache is not an expected current case and must not be substituted for seed9501.
- LS `resume` mode requires the exact original MAT checkpoint, including velocity/event state. Coordinate CSVs are insufficient for continuation. Newly generated benchmark checkpoints and historical LS MAT states are not included in the clean release; historical states are retained in the separate provenance archive. Without those states, audit CSVs or run a separately identified new production study rather than claiming exact continuation.
- MAT re-export scripts for the high-density configuration require the original MAT state. The already exported full-precision CSV is included and can be audited without that state.
- Some figure scripts mix archived data, generation, and optional replotting. They have not all been executed end to end. Do not claim that every manuscript panel is reproduced by running `main.m`.
- The numeric matrix `R2_C39_rdf_raw_numeric.csv` has no header. Read it with `readmatrix`, not as a headed table; otherwise one observation is lost.
- The archived 200-row `Table_R1_targetVF_raw.csv` is a distinct earlier sweep. Do not merge it with the 240-row fixed-final-radius VGPP/RSA-PBC reference or interpret it as missing cases from that benchmark.

The clean reference archive deliberately excludes generated MAT checkpoints, PNGs, temporary files, nested development ZIPs, and pre-resume CSV backups. These exclusions do not imply the excluded scientific states never existed; their exact original versions remain in the separate provenance deliverable.
